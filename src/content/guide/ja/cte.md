# 重要技術要素

CTE とは、その成熟度によってシステムが機能するかどうかが決まる、システムの一部分です。製品ではなく CTE を評価してください。「ノードは TRL 6」はサマリーであり、「エネルギーハーベスターは TRL 4」が評価です。

## CTE を見つける 5 つの質問

いずれかに「はい」と答えるなら、通常それは CTE です。

1. **新しいもの、または新しい使い方か** — 新しい環境、方法、規模で使うか。
2. **性能がそれに依存するか。**性能が不足した場合、ミッションは失敗するか。
3. **機能するかどうかに実際の不確実性があるか。**実証がなければ、成熟度は低いということです。
4. **知識のあるレビュアーが最初に質問しそうなものか。**
5. **次のマイルストーンに向けたクリティカルパス上にあるか。**

通常 CTE に **ならない** もの：定格の範囲内で使うカタログ部品、意図どおりに使うライブラリ、同じ環境ですでに実証済みのもの。

## 例

サンプルのセッションには 3 つの CTE があります：エネルギーハーベスター、電力管理モジュール、テレメトリーファームウェア。設置のような手順も CTE になりえます（種類は *プロセス*）。

## よくある誤り

| 誤り                                 | 対処                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------ |
| システム全体で CTE が 1 つ           | サブシステムの段階が明らかに異なる箇所で分割します。                           |
| 基板や部品ごとに CTE が 1 つ         | 常にステータスとエビデンスを共有することになる要素は統合します。               |
| すべてを重要に指定                   | ミッションの成否を左右するものだけを指定します。サマリーは最小値です。         |
| 何も重要に指定しない                 | 少なくとも 1 つを指定します。指定しないとシステムサマリーは算出されません。   |
| 「重要」を「大切」と解釈している     | 大切な部分が CTE になるのは、そのどこかが未実証である場合だけです。           |

デバイス規模のプロジェクトでは、通常 3〜8 個の CTE が適切です。
