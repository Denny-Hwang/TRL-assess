# ステージ対応表

> **参照モデルであり、公式の標準ではありません**。ステージモデルは組織ごとに異なります。コミュニケーションのために使用し、TRL の採点の根拠にはしないでください。

ここでは、一般的なハードウェア開発ステージモデルの 1 つを TRL に対応付けます。

:::figure stage-crosswalk:::

| ステージ | 開発上の呼称                    | 一般的な TRL | 主な目標                                                                 |
| -------- | ------------------------------- | ------------ | ------------------------------------------------------------------------ |
| 0        | コンセプト                      | 1–2          | 機会と、技術的に信頼できるアプローチを定義する。                         |
| 1        | 部品レベルの評価                | 2–3          | 主要部品を選定し、限界、ばらつき、統合リスクを把握する。                 |
| 2        | 概念実証                        | 3            | 基本的な技術的実現可能性を実証する。                                     |
| 3        | ブレッドボードプロトタイプ      | 3–4          | 信号チェーン、電子回路、アルゴリズム、ファームウェア、手法を開発する。   |
| 4        | 基板レベルのプロトタイプ（PCB） | 4            | カスタム電子回路、レイアウト、ノイズ、電源、インターフェースを検証する。 |
| 5        | 統合プロトタイプ                | 5            | 代表的な条件でエンドツーエンドの機能を検証する。                         |
| 6        | 小型化プロトタイプ              | 5–6          | フォームファクター、重量、熱挙動、パッケージング、使いやすさを検証する。 |
| 7        | 量産前提設計のプロトタイプ      | 6–7          | 設計検証、信頼性、規制対応と製造の準備を支える。                         |
| 8        | パイロット生産                  | 7–8          | 製造性、歩留まり、校正、出荷前検査、サプライチェーンを検証する。         |
| 9        | 技術移転 / ライセンス供与       | 8–9          | パートナーが製品を認定、製造、販売、サポートできるようにする。           |

## 範囲が広い理由

ステージが示すのは何を **製作したか** であり、TRL が示すのは **何をどこで実証したか** です。ベンチでのみ試験した小型化プロトタイプは TRL 4、関連環境で試験すれば 5、システムに統合してそこで実証すれば 6 です。ステージ 8〜9 は主に製造と商業の問題であり、TRL はそれを測りません。
