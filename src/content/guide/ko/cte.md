# 핵심기술요소

CTE는 그 성숙도가 시스템의 작동 여부를 좌우하는 시스템의 일부입니다. 제품이 아니라 CTE를
평가하십시오. “노드는 TRL 6이다”는 요약이고, “에너지 하베스터는 TRL 4이다”는 평가입니다.

:::figure cte-tree:::

## CTE를 찾는 다섯 가지 질문

다음 중 하나라도 “예”라면 대개 CTE가 있다는 뜻입니다.

1. **새로운 것이거나, 새롭게 사용되는 것인가** — 새로운 환경, 방식 또는 규모에서?
2. **성능이 그것에 좌우되는가?** 성능이 미달하면 임무가 실패하는가?
3. **작동할지에 대해 실질적인 불확실성이 있는가?** 실증이 없다면 준비도가 낮다는 뜻입니다.
4. **해당 분야를 잘 아는 검토자가 가장 먼저 물어볼 것인가?**
5. **다음 마일스톤까지의 핵심 경로에 있는가?**

대개 CTE가 **아닌** 것: 정격 범위 내에서 사용하는 카탈로그 부품, 의도된 대로 사용하는 라이브러리,
같은 환경에서 이미 입증된 모든 것.

## 예시

예시 세션에는 에너지 하베스터, 전력 관리 모듈, 원격 측정 펌웨어의 세 가지 CTE가 있습니다. 설치와
같은 절차도 CTE(유형 _공정_)가 될 수 있습니다.

## 흔한 실수

| 실수                              | 해결 방법                                                          |
| --------------------------------- | ------------------------------------------------------------------ |
| 시스템 전체를 하나의 CTE로 설정   | 하위 시스템의 단계가 눈에 띄게 다른 지점에서 나누십시오.           |
| 보드나 부품마다 하나의 CTE        | 항상 같은 상태와 증거를 공유할 요소는 합치십시오.                  |
| 모든 것을 중요로 표시             | 임무를 좌우하는 것만 표시하십시오. 요약은 최솟값입니다.            |
| 아무것도 중요로 표시하지 않음     | 하나 이상 표시하십시오. 그렇지 않으면 시스템 요약이 계산되지 않습니다. |
| “중요”를 “비중이 큼”으로 이해 | 비중이 큰 부품이라도 입증되지 않은 부분이 있어야만 CTE입니다. |

기기 규모의 프로젝트에는 대개 3~8개의 CTE가 적당합니다.
