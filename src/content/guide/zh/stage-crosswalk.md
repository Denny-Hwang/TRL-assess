# 阶段对照

> **这是参考模型，不是官方标准�**�阶段模型因组织而异。它们用于沟通，不能作为 TRL 评分的依据。

本页将一种常见的硬件开发阶段模型对应到 TRL。

:::figure stage-crosswalk:::

| 阶段 | 开发术语        | 典型 TRL | 主要目标                                         |
| ---- | --------------- | -------- | ------------------------------------------------ |
| 0    | 概念            | 1–2      | 界定机会以及技术上可信的方案。                   |
| 1    | 元器件级评价    | 2–3      | 选择关键元器件；了解其极限、变异性和集成风险。   |
| 2    | 原理验证        | 3        | 演示基本的技术可行性。                           |
| 3    | 面包板原型      | 3–4      | 开发信号链、电子电路、算法、固件和方法。         |
| 4    | 板级原型（PCB） | 4        | 验证定制电子电路、布局、噪声、电源和接口。       |
| 5    | 集成原型        | 5        | 在有代表性的条件下验证端到端功能。               |
| 6    | 小型化原型      | 5–6      | 验证外形尺寸、重量、热性能、封装和可用性。       |
| 7    | 面向量产的原型  | 6–7      | 支持设计验证、可靠性、法规符合性和制造就绪。     |
| 8    | 试生产批次      | 7–8      | 验证可制造性、良率、校准、下线测试和供应链。     |
| 9    | 技术转让/许可   | 8–9      | 使合作伙伴能够对产品进行鉴定、制造、销售和支持。 |

## 为什么范围很宽

阶段说明的是您**构建了什么**；TRL 说明的是您**演示了什么、在何处演示**。一个只在台架上测试过的小型化原型是 TRL 4；在相关环境中测试过则是 5；集成到系统中并在其中得到演示则是 6。阶段 8–9 主要是制造和商业方面的问题，而 TRL 并不衡量这些。
