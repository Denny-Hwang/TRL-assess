# 关键技术要素

CTE 是系统中其成熟度决定系统能否工作的那一部分。要评估的是 CTE，而不是产品：“节点处于 TRL 6”只是一个汇总；“能量收集器处于 TRL 4”才是一项评估。

## 找出 CTE 的五个问题

对其中任何一个问题回答“是”，通常就意味着您找到了一个 CTE：

1. **它是新的，或是以新的方式使用的吗**——用于新的环境、新的方式或新的规模？
2. **性能是否取决于它**？如果它表现不达标，任务是否会失败？
3. **它能否工作是否存在真正的不确定性**？没有演示就意味着就绪程度低。
4. **内行的评审人员会不会首先问到它**？
5. **它是否位于通往下一个里程碑的关键路径上**？

通常**不属于** CTE 的有：在额定范围内使用的目录件、按预期方式使用的软件库，以及已在相同环境中得到验证的任何东西。

## 示例

示例会话有三个 CTE：能量收集器、电源管理模块和遥测固件。一个规程（例如安装规程）也可以是 CTE（类型为*工艺/流程*）。

## 常见错误

| 错误                             | 纠正方法                                         |
| -------------------------------- | ------------------------------------------------ |
| 整个系统只设一个 CTE             | 在各子系统明显处于不同阶段的地方进行拆分。       |
| 每块电路板或每个零件各设一个 CTE | 合并那些状态及其证据总是相同的要素。             |
| 所有要素都标记为关键             | 只标记决定任务成败的要素；汇总取的是最小值。     |
| 没有要素标记为关键               | 至少标记一个，否则不会计算系统汇总。             |
| 把“关键”理解为“重要”             | 重要的部分只有在其某方面尚未得到验证时才是 CTE。 |

对于器件规模的项目，三到八个 CTE 通常比较合适。
